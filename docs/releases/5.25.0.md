# MidPulse 5.25.0 — lecture continue des dossiers d’équipe

## Parcours visible

Équipes OUAT → choisir division/groupe/équipe → ouvrir « Voir les parties » dans les pools, les « Parties sources » du comparateur ou le détail du suivi SoloQ. Les rafraîchissements des rangs/live et des effectifs ne referment plus les détails dont le contenu est inchangé. Le suivi SoloQ peut mettre à jour ses lignes en restant ouvert. La position de lecture et le focus sur un résumé sont restaurés sans défilement forcé du focus.

Les aperçus de rapport/export ne sont conservés ouverts que si leur contenu exact reste identique : une nouvelle date ou un nouveau rang peut les refermer. Un changement d’équipe au rendu invalide la restauration. Les changements explicites de navigation/filtres et les nouvelles collectes d’analyses restent des rendus ordinaires. Aucun état stocké sur disque, aucune ancienne donnée restaurée, aucun appel Riot ajouté.

## Diagnostic et vérifications

Reproduction par fixture DOM/VM du renderer : une reconstruction ordinaire perd l’attribut natif `open`. Le même rafraîchissement via `renderBackground()` conserve indépendamment les détails inchangés. Ce constat de code/test n’est pas une observation sur le poste Windows du propriétaire.

12 tests dédiés : ouvert/fermé, contenu modifié ou expiré, suivi évolutif, doublons indépendants, contexte d’équipe, autres vues, focus/scroll, véritables fonctions rank/live/effectifs, branches erreur/sans clé/délai/authentification, absence de persistance ou restauration HTML. Ils utilisent des objets DOM contrôlés et les fonctions réelles du renderer, pas un moteur de rendu natif.

La chaîne Windows conserve les tests complets, l’inspection de win-unpacked puis celle de l’installateur NSIS/app.asar avant publication. Le contrôle indépendant après publication est consigné sur la PR : commit, run Windows, asset, SHA-256, version et fichiers réellement extraits. Aucune livraison ne doit être dite vérifiée avant ce contrôle.
