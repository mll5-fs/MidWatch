# 5.10.1 — Spectate : demandes en double bloquées

Problème reproduit dans le renderer de la 5.10.0 : deux clics rapides déclenchaient
deux IPC Spectate. Le planificateur pouvait ensuite exécuter ces lancements l'un
après l'autre. La correction réserve une seule opération avant même la mise en
file des appels Riot, et désactive les boutons Spectate dans les profils pendant
la demande. Ouvrir un autre profil ne contourne pas ce verrou.

Après une acceptation du client local, une pause de 15 secondes évite une nouvelle
demande immédiate. Un timeout/transport interrompu ou un HTTP 5xx pendant le POST
est également considéré comme incertain et déclenche la pause côté principal.
Les échecs de pré-vérification Riot ne sont pas considérés comme des POST envoyés.
Les replis de route restent limités aux 404/405 ; aucun retry automatique après
un résultat ambigu. Aucune confirmation du démarrage de l'exécutable n'est ajoutée :
l'utilisateur doit toujours vérifier le client League.

Ce correctif ne prétend pas résoudre toutes les incompatibilités Spectate ni les
erreurs propres à une installation Windows. Le diagnostic sans clé Riot reste
disponible dans Réglages > Tester le client ouvert.

Validation locale : syntaxe, 185 tests. Scénarios de doubles clics, IPC concurrent,
changement de profil pendant la requête, pause après acceptation/résultat incertain,
absence de pause après préflight échoué et conservation du repli prudent.
Publication et inspection du nouvel installateur sont à confirmer dans le compte
rendu de livraison. Aucun test interactif Windows/LoL ou appel Riot réel effectué.

Sources consultées le 16 octobre 2026 : https://developer.riotgames.com/docs/lol
et https://developer.riotgames.com/apis/ (Spectator v5, limites des API et LCU
non officiellement pris en charge) ; https://dpm.lol/app/dashboard et
https://dpm.lol/premium (outils de spectate existants). Aucun endpoint local n'est
présenté comme un contrat public stable de Riot.
