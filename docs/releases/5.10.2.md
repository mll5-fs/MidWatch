# MidPulse 5.10.2 — Données liées au bon Riot ID

## Défaut reproduit

L'état transitoire de rang et de LIVE était indexé uniquement par identifiant de joueur LEA. Après correction du Riot ID, l'interface pouvait conserver le rang et le LIVE de l'ancien compte. Reproduction locale avec le code 5.10.1 : ancien rang et ancien LIVE toujours affichés sur un joueur dont le compte venait de changer.

## Correctif

- Chaque réponse de rang/LIVE porte une empreinte normalisée des comptes interrogés. L'interface ignore les réponses qui ne correspondent plus aux comptes actuels, y compris les réponses tardives.
- Dans une fiche joueur, « CORRIGER LE RIOT ID LEA » puis « Enregistrer », ou « Revenir au Riot ID LEA », recharge la liste depuis le processus principal et retire les observations de l'ancien compte. Le comparateur en cours est invalidé.
- Si une actualisation de rang est déjà en cours, une nouvelle passe est demandée après sa fin ; les limites Riot continuent à être respectées.
- Le rang reste une observation SoloQ publique ; un compte manquant, une erreur Riot ou une clé expirée ne devient pas un rang inventé.

## Vérifications prévues pour la livraison

Tests unitaires/VM sur changement de nom/tag/plateforme, ordre des comptes, rejet des anciennes observations et réponses tardives, rechargement après correction/réinitialisation, redémarrage après le dernier batch. Vérification Windows CI et du contenu du nouvel installateur requise avant d'annoncer une livraison vérifiée. Ces tests n'utilisent pas le client LoL réel.

Sources consultées le 16 octobre 2026 : documentation officielle Riot https://developer.riotgames.com/docs/lol et outil de scouting https://dpm.lol/ . Aucune hypothèse de MMR caché ni d'accès aux rangs via un contournement de l'API.
